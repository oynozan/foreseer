# TypeScript SDK

`foreseer.ts` is the reference implementation of FORESEER-SPEC v0.1: the
consensus engine, the verifier, and a reference TEE, in one dependency-light
package (only `@noble/hashes` and `@noble/curves`, no network code).

```sh
pnpm add foreseer.ts
```

Entry points:

| Import | Contents |
| --- | --- |
| `foreseer.ts` | types, byte stream, draws, rules, receipts, Merkle, presets |
| `foreseer.ts/rules` | rule validation, canonical JSON, hashing, evaluation |
| `foreseer.ts/verify` | the offline checks plus `verifyEpoch` |
| `foreseer.ts/reference` | `ReferenceTee` and test constants |

## Play a full epoch in fifteen lines

```ts
import { dice, merkleProof, receiptDigest, toBytes } from "foreseer.ts";
import { ReferenceTee } from "foreseer.ts/reference";
import { verifyCommit, verifyMerkleProof, verifyOutcome, verifyReceiptSignature } from "foreseer.ts/verify";

const tee = new ReferenceTee();
const { seedCommit } = tee.openEpoch();
const rule = dice({ target: 4999, mode: "over" });
const bet = tee.play({ clientSeed: "alice", rule });
console.log("rolled", bet.receipt.draws[0], bet.receipt.win ? "win" : "lose");
const signatureOk = verifyReceiptSignature(bet, tee.domain, tee.teeId).ok;
const { serverSeed, merkleRoot } = tee.closeEpoch();
const digest = receiptDigest(bet.receipt, tee.domain);
console.log({
    signature: signatureOk,
    commit: verifyCommit(serverSeed, seedCommit),
    outcome: verifyOutcome(bet.receipt, rule, serverSeed).ok,
    merkle: verifyMerkleProof(digest, merkleProof([digest], 0), toBytes(merkleRoot)),
});
// { signature: true, commit: true, outcome: true, merkle: true }
```

`ReferenceTee` is not a mock: it runs the real protocol without enclave
hardware and is the normative behavior the Go TEE mirrors byte for byte.

## Verifying a whole epoch at once

`verifyEpoch` runs every offline check across all receipts and tells you
exactly what failed and where:

```ts
import { verifyEpoch } from "foreseer.ts/verify";

const result = verifyEpoch({
    receipts,            // [{ receipt, signature }, ...] in betId order
    rules,               // every rule used, matched by hash
    domain: { name: "Foreseer", version: "0", chainId: 114n },
    serverSeed,          // revealed at close
    merkleRoot,
    closeSignature,      // optional, the epoch close signature
    expectedTeeId,       // the attested TEE address
});

if (!result.ok) {
    for (const f of result.failures) {
        console.log(f.check, f.betId, f.detail);
        // e.g. "signature 57n recovered address does not match expected teeId"
    }
}
```

Tamper with one byte of one receipt and the report names the betId with
three failing checks (signature, outcome, merkle); everything else stays
green.

## Deterministic building blocks

Everything consensus-critical is exported directly, so you can go as low
level as you like:

```ts
import { ByteStream, drawInt, MerkleTree, toHex } from "foreseer.ts";
import { canonicalRuleBytes, ruleHash, resolveOutcome } from "foreseer.ts/rules";

const stream = new ByteStream(serverSeedBytes, "alice", 0n);
drawInt(stream, 0, 9999);            // 3725 for the golden seed

const outcome = resolveOutcome(rule, serverSeedBytes, "alice", 0n);
// { draws: [3725], win: false, payoutBp: 0 }

new TextDecoder().decode(canonicalRuleBytes(rule)); // canonical JSON string
ruleHash(rule);                                     // 0x...
```

Consensus code contains no floats, no `Math.random`, no `Date.now`, and no
locale-dependent behavior; the only randomness in the package (seed
generation and `generateClientSeed`) uses WebCrypto and lives clearly apart
in the reference module.

## Testing your integration

Run the package's own suites against your checkout: `pnpm test` (unit,
golden vector, property, and end to end tests) and `pnpm stress` (throughput
plus a statistical randomness battery). If you port any part to another
language, `spec/vectors/` is the byte-exact conformance target; the Go
engine and the Solidity contract already pass it, so a fourth
implementation has three referees.
